# Phase 4b — SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the site the spec's full SEO model — metadata resolved with per-page/per-post override → global default → hardcoded fallback precedence, a `page_seo` table for route overrides, per-post overrides, `BlogPosting` structured data, an admin SEO form, and a `GET|PUT /api/v1/admin/settings/seo` endpoint.

**Architecture:** A new append-only migration adds `page_seo`. `db.SiteContent` gains a `PageSeo` map so `resolveMeta` stays a pure function of the cached snapshot and reloads with every content write. `resolveMeta` takes a small `metaOverride` describing the page's own title/description/image/noindex and applies the precedence chain. `internal/db/backup.go` carries `page_seo` (snapshot version 3). No MCP tools (Phase 5) and no `/docs` (Phase 8) here.

**Tech Stack:** Go 1.25, `modernc.org/sqlite` (CGO-free), `net/http`, `encoding/json`, `html/template`.

**Spec:** `docs/superpowers/specs/2026-09-16-johansenfoo-agent-first-site-design.md` (SEO; SEO surfaces)

## Scope

## Review Focus

1. **Precedence inversions.** A per-post `seo_title` must beat a `page_seo` row? No — the route row is the page-level override and the post is the subject; for `/posts/{slug}` there is no `page_seo` row, so the post wins over globals. For `/` and `/posts`, the route row wins over globals. Tests pin each layer.
2. **Noindex leaking or being ignored.** A site-wide `noindex`, a `page_seo.noindex`, and a post's `noindex` all produce `noindex, nofollow`; absent all three, `index, follow`.
3. **Title template misuse.** `title_template` with `%s` yields `Post | johansen.foo`; a full `page_seo.title` or `site_title` is never double-templated.
4. **`page_seo` not surviving Reload/reload/export.** It must appear in the snapshot map, the sitemap/pages, and export/import.
5. **XSS through operator-set SEO fields.** `seo_title`/`og_image_url`/`canonical_url` are operator input rendered into `<meta>` attributes; html/template must keep escaping them.
